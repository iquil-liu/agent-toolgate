# 审计日志设计

本文是离线知识检索演示使用的自造技术说明，讨论通用实现与验证方法。主题术语：JSONL、入参摘要、事件标识、追加写入、错误码。所有场景均为抽象示例，不关联任何真实组织或运行环境。

## 事件结构

每次工具调用产生独立事件，字段包含事件标识、工具名、状态、耗时和错误码。JSONL 每行一个对象，便于顺序读取与流式汇总。时间单位需要固定，避免不同模块混用秒与毫秒。

## 隐私与完整性

入参先规范序列化再计算摘要，不落原始消息。相同参数在字段顺序变化后应得到相同摘要。追加写入不能覆盖已有事件，写入失败应可见，否则调用成功却失去追踪证据。

## 故障排查

错误码用于聚合统计，事件标识用于定位一次实际调用。审计不应代替业务结果回读，日志成功只表示记录成功。验证时覆盖成功、参数拒绝、处理异常与并发写入，确保每次调用都有结论。
